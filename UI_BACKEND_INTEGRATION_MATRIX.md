# UI–Backend Integration Matrix

| UI area | Action / handler | API and source | Response/UI state | Failure state | Test status |
|---|---|---|---|---|---|
| Overview | Initial load, Refresh | `GET /api/dashboard`; PostgreSQL `predictions`, `prediction_outcomes`, `market_data` | Stored summary and recent decisions | Global retry banner | Verified by live API |
| Make prediction | `createPrediction` + `explainDecision` | `POST /api/predictions` → `POST /features`, `POST /predict` on FastAPI → `predictions` | Central templates provide the detailed accepted, abstained, and out-of-scope narrative; API-returned evidence and reason codes follow it. Forecast is shown only for valid `ACCEPTED`; unavailable fields are explicitly labelled as not returned. | 400 validation, 422 out-of-scope, 503 ML unavailable. Scope response preserves `prediction: null` and its API `error`. | API verified 2026-10-11: live `Onion/Abohar/Onion` returned `201 ACCEPTED`; stored `ABSTAINED` record retained `prediction: null`, risk score, signal, and verified reason; unsupported input returned `422 OUT_OF_SCOPE`. Browser UI unavailable in this session. |
| Prediction history | `getPredictions(offset, decision)` | `GET /api/predictions?limit&offset&decision`; `predictions` | Paged/filterable audit table | Truthful unavailable state | Live API verified |
| Reliability / uncertainty | Route queries | `GET /api/evaluation`, `/api/reliability`, `/api/uncertainty` | Persisted outcomes/signals | `NOT_RUN` where no outcome set exists | API verified |
| Failure memory | Route query | `GET /api/failures`; `failure_memory` | Recorded outcome cases | Empty/unavailable state | API verified |
| Outcome recording | `submitOutcome` | `POST /api/outcomes`; `prediction_outcomes` then `failure_memory` | Confirmed outcome and severity | 404 unknown, 409 duplicate | Live write/read verified |
| Model evaluation | Route query | `GET /api/research-results`; checked-in `ablation_results.json` | Explicitly labelled offline test table | Artifact-unavailable state | Live API verified |
| Dataset explorer | Route query | `GET /api/data`; bounded `market_data` aggregate | Row count/date range only | Loading/unavailable values | Live DB queried |
| System health | Route query | `GET /api/health` → PostgreSQL check + FastAPI `/health` | Separates reachability and readiness | Partial/unavailable badges | Live API verified |

Notes: FastAPI owns feature generation, model inference, novelty scoring, and the current historical failure-risk lookup. Express validates scope, orchestrates calls, and persists the ML decision without recomputing it. It normalizes legacy stored JSON reason arrays before returning records to the UI. The browser never calculates model values. The current ML response has a `reasons` array of verified text identifiers (not separate machine reason-code fields); unknown values use the neutral UI fallback. `failure_probability` is presented as a failure-risk score, not a calibrated probability. The database contains imported evaluation records; offline metrics are kept visually distinct from operational aggregate metrics.
